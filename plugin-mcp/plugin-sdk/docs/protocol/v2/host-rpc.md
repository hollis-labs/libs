# Host RPC profile 1 — field-level draft

Status: REVISION 2 — field-level schema APPROVED by orch-pp0 with changes (1)–(6) folded; consumer confirmation pending. Implementation remains separately gated. Protocol 2, optional reverse_rpc_version=1. This defines DTOs, not a working duplex transport or an acknowledgement. Schema source: protocol/v2/host-rpc.schema.json. No change to historical v1, Init, grants, capability policy, or host extensions. Current Serve validates and declines reverse offers.

Sources: accepted reverse-RPC 0163 (Tesseract item 01M41MHVKSR5NFSB5WVX7F1DX3), accepted capability ADR 0024 (01M41MHVD2GZFQXJ7MS8RMB2CN), stage3-plan (01M41T9SFNKNFCVZ2E4VCJSP69), current authored protocol/v2/schema.json + generate.py, capability/grant.go, docs/protocol/v2/{README,grants}.md. ## Structural contract

All SDK-owned objects are closed, field names exact-case, required fields present and non-null; optional fields are omitted. Duplicate decoded keys, invalid UTF-8/unpaired surrogates and depth greater than 128 reject before ordinary JSON parsing. There is no generic Call(method,args), service locator, caller identity, generation, trace or depth claim in context. Host namespace extensions are separately negotiated closed contracts, absent from this shared inventory.

OpaqueJSON is a bounded non-null courier for host/descriptor-owned payloads. Those owners must supply closed, exact-version schemas for every contained object where their contract requires them; the SDK does not invent fields, execute a query language, or infer authority from payload content. Nested null is allowed only by that owner's schema. Structural non-null policy does not turn arbitrary tool/resource JSON into SDK-owned DTOs. Arrays may be empty. Strings are Unicode; opaque tokens are compared exactly, without trimming or case normalization (nonblank validation does not normalize). Structural token limits are 4096 characters, narrower limits apply below, and byte budgets remain authoritative.

Every structural integer is a decimal integer token, never fraction or exponent. IDs and counters are JS-safe; profile request IDs are positive 1..9007199254740991. timeout_ms and schema_version are positive uint32. Portable opaque JSON follows Grant.scope: integer-form tokens within ±9007199254740991, all numeric values finite; larger integers must be strings. No bigint API. Base JSON-RPC separately supports string/signed safe-integer IDs; explicit null is invalid as a request and exists only in standard error replies when no valid ID is recoverable.

Reverse calls are requests with id, never notifications. All host/* notifications perform no effect and receive no fabricated reply. Standard parse/envelope/method/DTO failures remain -32700/-32600/-32601/-32602. An application error response uses -32010 and a positive profile ID. Duplicate active requests fence the connection without a second ambiguous reply. Response IDs correlate only with the initiator's outgoing direction; host id=1 and plugin id=1 may coexist. A result is validated against the pending method's result schema, not any convenient result union.

## Context, ancestry and host authority

Forward params have optional context = {binding_id?, timeout_ms}; if context exists timeout_ms is required. Reverse params always have context = {binding_id, timeout_ms, parent_call:{request_owner,id}} plus grant_id. Parent request_owner is host or plugin; id is positive safe integer. The schema deliberately shares one ReverseContext across all twelve methods.

binding_id is an opaque unpredictable host-issued reference (at least 256 bits of entropy), authenticated to the live process connection. It narrows current reviewed grants and verified caller authority; it is never a general bearer or SDK-minted identity. Runtime tuple and local connection instance live in the host ledger. grant_id selects a current grant and proves nothing by possession.

The host VALIDATES parent_call against its binding ledger before admission: unknown, terminal, wrong-owner and wrong-binding parents are refused with a typed error. Submitted ancestry is NEVER trusted for depth or deadline. Host-held ancestry reconstructs depth exactly once and enforces cycles/depth ceilings. Unknown, wrong-owner and wrong-binding parents all return target_unavailable/not_started with the SAME external detail parent_invalid and the same safe message. This prevents an existence oracle. Only a terminal parent of the SAME binding may return parent_terminal. The host audit retains the exact internal refusal reason in bounded metadata; wire errors never expose it. Authorization/binding ownership checks precede disclosure of terminal status. Unauthorized grant selection remains capability_denied; a verified callback cycle is scope_denied/detail callback_cycle and depth overflow budget_exceeded/detail depth_exceeded.

timeout_ms is a REQUEST. Host clips it to min(parent remaining, method ceiling, offer limits), and additionally to binding/grant expiry and current caller/root deadline. It never extends any deadline. A positive large request is clipped, not granted in full; zero remaining time is deadline_exceeded/not_started. Initiator time starts before encoding/admission; copy, queue, schema validation, transport and backend all spend the same budget. Local monotonic clocks do not require cross-machine synchronization. Parallel children reserve shared bytes/effects/tokens atomically.

No detached callback can forge parent 0, omit a binding, or borrow another invocation. Background work needs an explicit host-issued live background binding and a live host-recorded parent call under an approved background grant; a workflow callback always requires its run-bound binding. This context ruling does not add an issuance method. If the host has no such delivery contract, background reverse calls are unavailable. Only explicitly granted host/log is allowed during init/load/bounded cleanup, with a provisional/cleanup binding and a concrete parent_call = {request_owner:"host", id:<the positive safe ID of the in-flight plugin/init, plugin/load or plugin/unload request>}. The host records that lifecycle request in its ledger and validates this reference just like any other parent. A completed/unrelated lifecycle request cannot authorize provisional logging. Other services return target_unavailable outside active ownership. Revalidation occurs at admission and again before effects commit.

## Closed method table

Every Params row implicitly begins with required grant_id and ReverseContext context. Brackets below mean optional omission. Shared tokens are nonblank.

| Method / descriptor | Additional params | Successful result |
|---|---|---|
| host/storage/get / storage.read | key | found; when true, value and revision required; when false, both omitted |
| host/storage/put / storage.write | key, value, expected_revision, operation_key | operation_key, revision |
| host/storage/delete / storage.write | key, expected_revision, operation_key | operation_key, deleted:true, revision |
| host/secrets/get / secrets.read | secret_ref | value_base64, expires_at |
| host/egress/request / egress.request | method, url, [headers], [body_base64], [operation_key] | status, headers, body_base64, [operation_key] |
| host/events/publish / events.publish | event_name, payload, operation_key | operation_key, accepted:true, event_id |
| host/log / log.write | level, message, [fields] | accepted:boolean |
| host/readonly/query / readonly.query | resource, schema_version, params | resource, schema_version, data |
| host/mcp/list_tools / mcp.reach | server_id, [cursor] | server_id, tools, [next_cursor] |
| host/mcp/call_tool / mcp.reach | server_id, tool_name, tool_binding, arguments, [operation_key] | content, is_error, [structured_content], [operation_key] |
| host/mcp/cancel_call / mcp.reach | target_call_id | accepted, already_terminal (exactly one true) |
| host/bindings/renew / existing binding grants | requested_lease_ms | same binding_id, expires_at, remaining_budgets |

Storage is owner-private logical KV, never a filesystem API. Put expected_revision is REQUIRED; explicit null means create-only, never unconditional overwrite. Non-null revision means compare-and-set. Revisions are monotonically increasing per key and NEVER reused, including across tombstones and restarted incarnations. They remain opaque string tokens on the wire; hosts own their ordering. Delete requires a non-null revision and returns a strictly higher tombstone revision; delete of an absent key or stale revision is conflict. A put with expected_revision:null after deletion is a create-only success with a revision strictly HIGHER than the tombstone. Tombstones preserve the revision high-water mark. Values are non-null OpaqueJSON. Get found:false distinguishes absence from an empty value.

Every business mutation requires operation_key. Mutations are storage put/delete, event publication, effectful egress and effectful MCP tools. Log telemetry, request cancellation and lease renewal are not business mutations and do not mint operation keys. Effectful MCP requires the key based on the host-pinned tool effect (write/destructive); the plugin does not submit an effect override. Egress requires it structurally for POST/PUT/PATCH/DELETE and at runtime whenever host policy classifies another accepted verb as effectful. GET/HEAD/OPTIONS are not automatic authority to perform effects.

Receipts are keyed by (owner_id, method, effective target, operation_key), NOT host_instance or owner_generation, and bind a host-defined canonical semantic input digest. Store the canonical tuple/generation of the original execution INSIDE the receipt as provenance, outside its deduplication key. A restarted incarnation retrying a pending write consults the existing owner's receipt instead of re-executing solely because its generation changed. The service must serialize concurrent same-key attempts; this does not allow a stale connection to regain authority. Host returns the ORIGINAL same-input result (including echoed operation_key), rejects differing input with conflict before execution, and never re-executes an in-flight duplicate to obtain a receipt. Transport-only timeout/parent variation cannot broaden authority and is not business input; current authority is revalidated before disclosing a receipt. Egress/MCP replies echo operation_key exactly when it was submitted, omit it otherwise. Receipt persistence/retention is service-owned; restart/lost receipt may leave unknown_outcome. Keys are not retry authorization or exactly-once transport; no automatic mutation retry.

Secrets are exact broker-approved references; empty decoded bytes are valid, not absence. expires_at is UTC RFC3339 with Z and up to nine fractional digits, matching grants. Host enforces validity/expiry. SDK registers decoded secret bytes with its redaction tracker BEFORE returning them to plugin code. No keychain enumeration, inherited environment fallback or local secret database.

Egress method is one of GET, HEAD, OPTIONS, POST, PUT, PATCH, DELETE; absolute HTTPS URL only, no userinfo credentials or fragment. Header lists preserve duplicate names, each closed {name,value}; names are HTTP tokens and values must exclude CR/LF/NUL. At most 128 entries, name at most 256 characters/value 8192. Body omission means no request body. Results require headers (empty [] valid) and body_base64 (empty string valid); status is 100..599. Host scopes methods/destinations/bytes, validates every redirect/resolution/pinned actual connection, disallows private/loopback/link-local/metadata destinations and proxy bypass. Redirects default off. These are host-adapter obligations, not schema proof.

Events name catalog-approved owner events (max 256 characters); payload schema is exact and host-owned. Cannot inject lifecycle/core/permission events. Rejection is a typed error; accepted:false does not stand in for a denied mutation.

Log level is debug/info/warn/error; message max 16384 characters, optional fields list of closed {name,value} (max 128, unique exact-case names, name max 256). Values are bounded OpaqueJSON. accepted:false means an explicitly non-effectful telemetry drop under host policy; denial/rate limit may instead be typed failures. Host redacts and does not select arbitrary sinks/paths from metadata.

Readonly resource is an exact approved catalog name (max 256). resource/schema_version MUST match the selected grant descriptor scope; host validates params/result against its per-resource closed schema. Result echoes exact resource and schema_version. SDK validates envelope, portable JSON and byte budget only; opaque params cannot be SQL, service names or arbitrary endpoints without a separately reviewed resource schema that this profile does not define.

MCP list server_id is canonical and approved. Cursor is opaque host-issued, pinned to the same scope/snapshot, omitted at the first page; next_cursor omitted at the end. tools empty [] valid, max 256 per response (byte budget still applies). Each tool is closed {tool_name, input_schema, effect, tool_binding, description?, output_schema?}; effect read/write/destructive is host-reviewed metadata. Tool schema documents are host-owned OpaqueJSON. The host issues opaque tool_binding pinning target tuple and reviewed definition digest. SDK NEVER constructs, infers or remints it. Call rechecks binding/server/tool/schema/effect/caller policy; stale binding is target_unavailable/detail stale_binding and needs fresh discovery, never cached-name retargeting. content is the bounded normal MCP content array whose items are carried as OpaqueJSON (runtime host/tool schema enforces content blocks); is_error is required and remains a tool outcome, never authority denial. Optional structured_content is host-owned. Cancel targets only this connection's plugin-owned host/mcp/call_tool ID in the same cancellation table; unrelated direction/actor/type is scope_denied, terminal own call returns accepted:false/already_terminal:true. Transport rpc/cancel is a separate closed notification in the duplex slice.

Renew requested_lease_ms is positive <=300000. Same binding_id is returned; expiry <= min(now + requested lease, parent/run deadline, current grant/caller expiry). Renewal is normal bounded admission, never privileged unlimited control. Reject expired/revoked/wrong-generation references with target_unavailable; cannot revive on reconnect or widen scope/reset spent budgets. remaining_budgets contains required positive timeout_ms and optional JS-safe nonnegative bytes/effects/tokens. A tracked dimension must be returned, including zero; untracked dimensions are omitted and do not imply unlimited authority. Renewal rechecks grant_id against the binding's current grants.

## Typed failures

Application failure envelope: {jsonrpc:"2.0",id,error:{code:-32010,message,data}}. data is closed {contract:"host-rpc/1",code,request_id,effect_state,retryable:false,detail?}; request_id equals enclosing id. message is sanitized and <=256 characters; the error obeys the frame budget. Optional detail is the CLOSED enum stale_binding | callback_cycle | depth_exceeded | parent_invalid | parent_terminal, never free text, arguments, URLs, SQL, tokens, secrets or stacks. capability.FailureDetail in capability/errors.go is the SINGLE source of this vocabulary: new values must land there as well; RPCData rejects unknown details. At source d8cd924 the leaf has only stale_binding/callback_cycle/depth_exceeded and request_id:string; task-pp0-2's follow-up adds the two final parent details and changes request_id to the schema's positive safe INTEGER. Do not change this schema to match the stale leaf string. request_id must equal the envelope integer id; empty/missing/string values are invalid. Symbolic codes are stable and shared; never discriminate by message.

| Code | Meaning |
|---|---|
| invalid_request | Semantic binding/scope/operation-key input invalid |
| unauthenticated | Connection subject cannot be authenticated |
| capability_denied | No current permitted grant |
| scope_denied | Target/effect exceeds scope, wrong cancellation actor or callback cycle |
| unsupported_capability | Recognized descriptor not supported by this host |
| target_unavailable | Inactive/revoked/stale target or invalid ledger parent/binding |
| budget_exceeded | Non-time bytes/effects/tokens/depth exhausted |
| rate_limited | Bounded admission/rate exhausted before execution |
| cancelled | Explicit cancellation with no uncertain commit |
| deadline_exceeded | Deadline exhausted with no uncertain committed effect |
| unknown_outcome | Effect may have committed without authoritative outcome |
| internal_error | Sanitized panic/unclassified backend failure |
| conflict | Expected revision mismatch or key reused with different business input |

effect_state is not_started, not_committed, committed or unknown. Before transmission/admission definite refusal is not_started. After possible transmission of an effectful call, ambiguous connection loss/deadline is unknown_outcome/unknown, never automatically retried. Reads with lost replies preserve target_unavailable/deadline_exceeded. A known completed commit returns the normal recorded success even if cancellation raced later; late replies cannot retroactively change a caller's returned timeout. ErrCancelled hook veto is distinct from transport cancelled.

## Size and runtime validation

Params and result each have a hard 1048576-byte (1 MiB) encoded UTF-8 JSON budget, counting braces/keys/escaping and BASE64 TEXT; profile outer frame max is 8388608 bytes including LF (CRLF counts both terminators). Offer/grant/method/local limits may narrow budgets, never silently widen an offered frame maximum. Base64 must be canonical padded RFC4648 without whitespace/URL-safe alphabet; empty valid. n decoded bytes require 4*ceil(n/3) base64 characters plus JSON overhead; enforce decoded-byte grants too. Bound before copying/parsing/encoding as well as before writing. Character maxLength is supplemental, not a byte cap. Schema cannot enforce encoded length, duplicate keys, token spelling, live ledger policy, header CRLF checks, conditional tool effects, receipt equality or reply correlation; later Go/TS validators and host implementations must enforce them.

Primary sources read at plugin-sdk d8cd9249d0cef7c5a04ced671ada94ed39aa34a0. Existing generate.py reads only schema.json and cannot render oneOf/allOf or the new conditional result variants. This slice supplies an authored schema/method table; later 3e code extends generation and closed Go decoding without adding a mutable-file sync test. Implementation interface is HostServiceHandler, distinct from existing HostServices Init offer; generate typed fixed helpers only.

## Review decisions and conformance vectors

Field-level choices APPROVED by PP0 (revision 2): header/log fields use arrays of closed entries; storage delete requires CAS and returns a tombstone revision; top-level storage/query/tool courier values are non-null; mutation receipts echo operation_key; readonly result echoes resource/schema_version; MCP list tool metadata uses pinned opaque tool_binding and host-owned schemas; cancel booleans are exclusive; remaining budget dimensions omit untracked counters. These are the approved field-level refinements to 0163; they do not claim implementation or transport conformance. Review changes also fix parent existence-oracle protection, the closed detail vocabulary, owner-stable receipt keys with generation provenance, monotonic revisions across tombstones, and concrete lifecycle parents for provisional logging.

Host-rpc fixture draft is an artifact beside this document. It separates structural vectors from HOST-POLICY scenarios; none has been executed. Structural vectors cover all twelve positive DTOs plus missing/extra/wrong-case/null context, invalid decimal tokens, unsafe integers, conditional mutation keys and put null-vs-omitted revision. Policy vectors require a fake host ledger/backend and prove unknown/terminal/wrong-owner/wrong-binding parent refusal (zero backend effects), clipped timeouts, depth from ledger, stale tool binding, scoped query schemas, receipts and no auto-retry. Fixtures cannot prove a real host's credential/egress/secret policy. No profile acknowledgement until later Go + Node child replay and pinned host interop pass.
