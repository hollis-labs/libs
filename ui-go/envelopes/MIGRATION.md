# Migration: go-envelopes -> libs/ui-go/envelopes

`github.com/hollis-labs/go-envelopes` moved into the libs monorepo as `ui-go/envelopes/`, with its full git history (42 commits, 2026-05-08 to 2026-10-02; source HEAD `6480ac9d2d61`). The standalone module is no longer where new work happens.

## What changed

- **Module.** The code is now part of the `github.com/hollis-labs/libs/ui-go` module (one `go.mod` for all of its packages). Release tags of the old module (v0.1.0 v0.1.1 v0.2.0 v0.3.0 v0.4.0 v0.5.0) were not carried over; the first release of the new module will be tagged `ui-go/v0.1.0` (not tagged yet).
- **Import paths** in code, documentation and tests were rewritten mechanically, whole path segments only. Links to the old repository's web pages and the history in `CHANGELOG.md` are left as written.
- **API.** No symbol was renamed or changed by the move.
- **Links.** Commit and release links in `CHANGELOG.md` and `docs/releases/` still point at the old repository, where those commits and tags exist; they were not rewritten.
- **Dependency versions.** Everything this lib required is at the same version it had before.
- **Files not carried to the new location** (git history still has them): `go.mod`, `go.sum`.
- **Behaviour that follows the module path.** `envelopes.ModulePath` identifies the module that owns the catalog and is compared with the module paths in the binary's build information. It is now `github.com/hollis-labs/libs/ui-go` (the module), not the package's import path, and was `github.com/hollis-labs/go-envelopes` before. Catalog source identity (`Source.Module`) and the module line of generated TypeScript therefore change; so does the "Code generated by" header text there. A consumer that compares `Source.Module` with the old string must be updated.
